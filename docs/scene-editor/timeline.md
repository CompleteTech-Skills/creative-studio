# Native timeline editing

`editor3d_timeline.prepare_timeline_commands` prepares bounded native Scene3D document replacements. `apply_timeline` publishes these through `EditorRepository.transact_native`; every request supplies the expected revision, snapshot digest, and idempotency ID. Undo/redo and recovery use the existing repository. Original project files and previous repository revisions remain immutable.

Authenticated server dispatch can register `editor3d_timeline.routes()`. Mount `mountTimeline` from `assets/editor3d/timeline.js` with `hatchEditor.registerExtension(mountTimeline, container)` after the viewport initializes. The adapter does not implement an alternate HTTP server or save engine. Do not expose mutation endpoints without the viewport server's authorization and request limits.

Supported commands cover exact integer key insertion/replacement/move/deletion, shared evaluator interpolation modes, clip creation/binding/unbinding, shot creation/duplication/settings/deletion, scene creation/duplication/rename/deletion, and exact project document order. Clip speed and loop semantics are validated by the canonical schema. Clip sources remain immutable. Supported authored channels match the native evaluator: object translation, rotation, scale, visibility, material references, light intensity, and world exposure. Native rig/morph clips remain capability-bound native clips; this adapter does not claim direct bone/morph curve authoring.

`timeline/evaluate` requires an exact saved revision/digest, a selected shot path, and an integer frame or `{numerator, denominator}`. It delegates to `scene3d_evaluate.evaluate_scene`, preserves rational frame/time values, and respects half-open shot intervals. The browser preview uses evaluated node transforms, with keyboard-operable controls for tracks, keys, playback, clip reuse, shot order and camera/duration settings. Playback derives integer frame indices from the shot's rational frame rate and a monotonic clock; server responses carry their saved revision.

Current validation uses actual native triangle projects, immutable saved document promotion, re-open, interpolation, clip reuse, shot reorder/settings, undo/redo and invalid batch rejection. `test_rig_editor3d_timeline.py` is optional rig-gate coverage; execute it with the rig test environment and `PYTHONPATH=scripts`.

Issue #104 remains open until integrated browser validation, autokey integration with persistent viewport commits, curve-editor visualization, direct bone/morph channel authoring, and full parent acceptance are implemented and independently reviewed. The native snapshot extension (`document_replacements` and `project_selection`) and evaluator are dependencies owned by Scene3D; their current integration requires native-owner review. No production render or visual approval is implied by these tests.

When the viewport supplies `registerCommitInterceptor`, the timeline's Autokey checkbox converts a transform-only commit into three native key-upsert commands per target, within one repository transaction. Mixed transform/non-transform batches are rejected while autokey is active; other operations proceed normally. Autokey remains disabled when that extension API is absent. Integrated browser confirmation is still required.

The combined native publisher accepts simultaneous graph edits and explicit shot-document replacements only for shots on that edited graph scene. It coalesces each shot to one new version while retaining original graph scene/shot associations. Asset, clip, or other document replacements combined with a graph are rejected before copying/publication; use document replacements without a graph for transitive timeline publication.

`timeline/curve` samples 2–33 exact rational frames through the same native evaluator and returns only the selected numeric channel. The UI requests 17 samples and plots their real returned values. TRS channels use the native owner's `state.channels` response, representing evaluated local animation/path inputs before graph constraints. No client interpolation or quaternion decomposition is used. The plot connects samples for navigation; it is not a new curve algorithm or a guarantee about unsampled extrema. Key value/frame and interpolation edits use the existing native commands. Visibility, intensity, and world exposure curves are also supported. Material-reference curves remain editable as keys through the API, without a numeric plot.
