# Structured planning adapter

`director_planning.generate_structured(request, store, project_root=..., configuration=..., authorize_call=...)` implements the native `PlanningProvider.generate_structured` result contract. Configuration explicitly names a provider, model, allowed endpoint hostname, limits and optional credential environment variable. Only HTTPS `/v1/responses` or labelled literal loopback HTTP fixture transport is accepted; redirects are refused. No default credential or endpoint is inferred.

`template(role)` publishes version 1 interpreter, story, shot, asset, identity, animation, camera, QA and revision instructions, exact native schemas and content hashes. The native request selects brief, story, shots or revision. References are verified against exact bytes, bounded and labelled as untrusted data. Original prompt and frozen constraints remain separately encoded. Provider requests disable storage and tools and demand schema output. Only completed assistant text output is accepted. Responses preserve reported model identity, raw response, usage, repair history and output bytes; unknown measurements remain unknown. Schema repair is bounded by the native request, and every paid attempt requires the application-owned budget callback.

The application owns the store directory and supplies verified policy evidence and budget authorization. A durable dispatch claim precedes network submission. An interrupted attempt or reused idempotency key cannot silently dispatch again; reconciliation is required. Exact completed requests replay immutable verified results. Network uncertainty is reported as `awaiting_external_result`; rate limits and failures do not automatically retry. Stores must remain retained to preserve this guarantee.

Tests use an actual loopback HTTP fixture server and explicitly mark its artifacts `fixture: true`. They establish transport and validation behavior, never model quality or live execution. No planning provider endpoint or credentials were configured in the recovery environment. Live brief, story, shot and revision acceptance required by issue #32 remains outstanding; this implementation does not close that issue.

For a configured live environment, export only the credential named by the configuration's `credential_env`; supply a configuration JSON file with `provider_id`, `model`, `endpoint`, `allowed_hosts`, `credential_env`, `paid`, and `fixture_transport: false`. Keep credentials out of configuration JSON. Inspect templates with `python scripts/director_planning.py template interpreter` (likewise `story`, `shot`, `revision`). Bind the native request's template hash and schema ID to that output; provide exact policy and context artifact references under the project root. Use a separate request idempotency key for each intended stage, preserve frozen decisions, and record actual provider usage.

Run each stage through `python scripts/director_planning.py generate --request REQUEST.json --configuration CONFIG.json --project-root PROJECT --store EVIDENCE`. The immutable evidence directory contains the exact request and raw response artifacts and result envelope. The CLI supports configured free providers; paid providers fail closed because the CLI cannot invent a native budget reservation. Applications execute paid runs through the Python API with their native ledger authorization callback. Free endpoints still require explicit verified network/provider policy. Run brief, story, shots and revision separately; inspect real content and metadata before claiming live acceptance. Fixture transport never counts as live acceptance.

Platforms without the native descriptor-relative secure artifact reader return `blocked_capability` with `DIRECTOR_PLANNING_PLATFORM` before dispatch. There is no weaker production file-read fallback. Transport tests on those platforms substitute a test-only reader for private fixture files, while separate tests exercise the actual unsupported reader and assert zero provider calls. Passing those transport tests does not establish secure artifact I/O support on Windows.
