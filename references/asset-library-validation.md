# Native verification of registered normalized GLB

`asset_library_validation.validate_asset(library, reference, limits=None)`
takes an exact `AssetRef` and returns a versioned technical report or raises a
typed `RigError`. The supported input is an imported self-contained version
with a single `payload` record named `normalized.glb` in GLB format. The
verifier supports mesh-bearing props, characters, rigs, animations, materials,
and textures. The registered category must match the capabilities actually
observed during verification.

The AssetLibrary checks the immutable manifest and payload inventory, including
the canonical records where durable storage is enabled. The verifier stages
only the exact normalized GLB in a private temporary directory. It rejects any
buffer or image URI, including data URIs, before invoking readers that could
resolve resources. The native decoder and the offline Khronos validator each
read the staged path, and their reported file digests must match the registered
payload. The default validator installation is pinned by the repository lockfile.
A configured offline installation reports the version it actually ran. Results come from those reads
and the native validators. Stored importer reports, diagnostics, and original
source paths are unnecessary for inspection. Their blobs still belong to the
AssetLibrary's integrity check.

The report identifies the normalized payload by logical path, byte length and
SHA-256. It includes selected-scene parentage and world transforms, measured
base-mesh geometry, authored material and texture object counts, dimensions and
digests of decoded embedded images, and validated skeleton, authored skin and
clip summaries where present. The verifier counts native rigid fallback
bindings separately from authored skins.
Inverse-bind digests cover the canonical native matrices generated by import.
A texture category requires a validated texture object that references a decoded
image. Independent validation includes the validator version and requires an
explicitly untruncated issue report with zero errors and a nonnegative warning
count.
The verifier compares source and decoded clip counts and reconciles each ordered
track's destination, path, interpolation and full key-time sequence against
the corresponding source channel and its input accessor. The native decoder
provides the mapping from numeric glTF node indices to bone and mesh IDs.
Each track reports the numeric source node. A morph weight channel contributes
a track for each active primitive of its target node and includes the numeric
primitive index on each track. Animation summaries give the exact source
key-time endpoint and the native playback duration. Each track includes a key
count, rational endpoints and a SHA-256 of the complete verified key-time
sequence in the native canonical JSON encoding. The sequence comparison
preserves the sign of zero.
Skeleton hierarchy and rest measurements are represented as digests. The
report omits embedded names and arbitrary validator messages. Errors retain
typed codes, retryability and applicable integer counts.

Callers can tighten native resource limits. Byte and memory admission precedes
payload retrieval, and native preflight budgets geometry, hierarchy, animation copies
and embedded texture work before validation. It accounts for generated native
morph position arrays, repeated inverse binds and per-binding skeletal passes.
The report's `resources` section gives the selected-scene node and
primitive-instance counts, accessor and embedded image inventory counts, and
the sum of encoded image view lengths and header dimensions in pixels. An image
view is counted for each image record that refers to it. The glTF load estimate
uses the native preflight's geometry-only method and array estimate. The
verification reserve includes that estimate along with geometry analysis,
animation, generated native arrays and verification overhead. The native decode
budget is the profile's memory limit minus that reserve. Raster admission
charges 16 bytes per image pixel against half the decode budget, rounded down,
with a separate 16,777,216-pixel cap per image. These byte estimates describe
admission for this verification pass. Process memory, GPU allocations and
renderer performance require their own measurements. Node, clip and key limits
bound the report. The timeout applies to the Khronos subprocess. The
in-process native checks use the resource admission limits.

The `capabilities` list describes data observed in this normalized payload
under the native format checks. Support for a particular renderer or original
source format requires separate evidence. Verification leaves the library
read-only and reports visual review as
`unreviewed` and production approval as false. Prefabs, environments, linked
assets, original/alternate payload formats, Blender, skeleton-free animation,
and renderer execution remain outside this slice. The full #140 acceptance
and its #139 prerequisite remain open.
