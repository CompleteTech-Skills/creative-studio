# Native liquid engineering profile

`python scripts/physics_liquid.py demo NEW_DIRECTORY --blender /path/to/blender`
executes the pinned Blender 4.5.3 LTS build's actual Mantaflow liquid solver,
saves its native project and caches, reopens the project in another process,
and compares all output frames with the original evaluated geometry and an
independent gzip BOBJ mesh decoder. `verify CACHE_DIRECTORY` checks the full
artifact inventory, source identities and those retained comparisons without
running Blender. Hashes establish integrity, not authenticated provenance.

This separate adapter admits one unrotated cubic water domain with 8–64 cells
per side, 2–64 zero-origin output frames, actual sphere/box source meshes,
static obstacles, or authored translating kinematic obstacles. It records
native adaptive CFL timing separately from the common world output interval.
Density is fixed at normalized water settings; viscosity, initial inlet
velocity, emission interval and explicit domain boundaries have bounded
settings. Spray, foam, bubbles, dynamic rigid-fluid feedback, external force
fields and solver continuation are rejected or unavailable. It does not
advertise these capabilities through the rigid-body backend.

The example pours water into a simple container; `--moving` adds an authored
paddle. Geometry is generated by the native solver, while paddle motion is an
explicit animation input. This is an engineering fixture, not production art.
Three original and reopened PNG frames support visual inspection. When liquid
entirely leaves an open domain, Blender may expose the domain cage as evaluated
geometry; the worker identifies the explicitly empty native BOBJ cache and
records no liquid surface for that frame. The independent decoder checks that
empty state rather than treating the cage as liquid.

Jobs stage into an exclusive temporary destination and publish only after all
checks pass. Existing destinations are preserved. Source closure, cache files,
PNG dimensions, finite topology, resources and native version are checked.
The process owner enforces deadlines, memory/output limits and cancellation.

## Acceptance status

The implementation is a bounded increment toward issue #180. Native bake,
reopen, mesh decode, evolving geometry and parameter-sensitive fixtures are
covered by opt-in `test_rig_physics_liquid*.py` tests. Run with
`HATCH_PHYSICS_BACKEND_TEST=1` and `HATCH_BLENDER` set to the pinned executable.
Unavailable Blender is an explicit failure, never simulated evidence.

The matched 48-frame, resolution-24 pouring experiment additionally runs
`physics_liquid_acceptance.evaluate_caches` on its baseline, viscosity .01,
and uncontained/open-bottom caches. It verifies the complete native cache
inventories and exact fixture world, settings and source meshes before
independently decoding every BOBJ surface. All other viscosity-pair inputs
are identical. The domain bottom is open in all three acceptance cases, so
the domain boundary cannot mask leakage through the container floor. The
uncontained control changes only the container geometry. The stationary/moving paddle
experiment remains a separate geometry-response check.

The quantitative acceptance profile uses canonical metres and h=3/24=.125 m:

- At every output frame in both contained viscosity cases, measure the greatest surface excursion beyond the
  container's outer x/z walls (+/-.9 m) or below its floor (0 m). Include
  above-rim splashes in this conservative envelope. Require excursion <=2h
  (.25 m): one cell for obstacle rasterization and one for the meshed
  interface. This is an engineering acceptance envelope, not a proved
  discretization-error estimate or a guarantee of sub-cell impermeability.
- Clip actual surface triangles to the interior observation box, x/z +/- .8 m,
  y from floor-top minus h to rim minus 2h. Require an initially absent pool
  (area <=h²) and a retained patch >=16h² (.25 m², a 4x4-cell equivalent)
  in both viscosity cases in every final-quarter frame (36–47). The uncontained control must have
  <=h² in those same frames. This distinguishes visible retained liquid
  from immediate drainage without interpreting interface area as mass.
- Detect first contact when the lowest surface reaches floor-top plus h in
  each viscosity case. Use the first six frames after the later contact,
  after emission ends and before the late retention window. Measure the
  maximum radial extent of surface vertices below rim minus 2h. Higher
  viscosity must reduce mean impact spread by >2h, allowing one cell per
  independently meshed radial interface, with positive reduction at every sample.
  Both cases must retain a >=16h² surface patch at each spread sample;
  disappearing high-viscosity fluid cannot establish reduced spread.
  The window follows contact, not whichever frames happen to maximize the
  difference. Zero response, a reversed effect and a sub-cell effect fail.

These are output-frame **surface geometry proxies**. They bound observed
surface position and demonstrate retained surface and viscosity response;
they do not measure liquid mass, leakage flux, continuous-time escape,
velocity from changing topology, or disappeared subgrid droplets. The .25 m
comparison/envelope is distinct from the 2e-5 m native/reopened coordinate
agreement check. The latter measures cache agreement only.

With `HATCH_LIQUID_EVIDENCE` set, the actual native test retains every sampled
metric, check, physical threshold, world/cache hash, backend identity, setting
and resource measurement in `surface-acceptance.json`, including failed
physical results. Existing immutable caches can be assessed without rebaking:

```
python scripts/physics_liquid_acceptance.py --baseline CACHE/baseline \
  --viscous CACHE/viscous --uncontained CACHE/uncontained --output NEW_REPORT.json
```

This command never changes the caches, and exits nonzero for failed physical
acceptance. The assessor consumes the same bounded, immutable byte snapshot
that passed cache verification, including the native mesh, source/settings,
worker and manifest identities. Concurrent changes to caller paths after
verification cannot replace the measured geometry or its recorded hashes. Analytic clipping and adversarial metric tests establish the
measurement implementation; only actual decoded solver caches establish the
native experiment. Current-head CI and independent review remain required.

Historical measurement development retained its first failed result:
`physics180/numerical-acceptance-first.json` in the coordination evidence.
The original assessor additionally required a >h reduction in every individual
frame. Actual decoded contact began at frames 16/17, so the resulting window
18–23 included an early transient with .108139 m reduction; its six-frame mean
was .296371 m. The per-frame >h check failed despite exceeding the declared
.25 m mean-effect envelope. The revised profile retains the .25 m mean
threshold and requires a positive direction throughout the window; it permits
an individual early transient to remain below one cell. This adjustment and
the failed report must remain visible to independent review. It is not a new
solver execution or a claim of current-head CI success. Those immutable native
caches were produced at d8c2ae44bc5d9bb1e88f249692a94cf18977d3c9, with
historical directory name `physics180/final-d91cabf`.

Those historical contained cases used a closed domain bottom coincident
with the container floor. They establish preliminary surface measurements,
but cannot isolate floor retention from the domain boundary. The final
profile requires the same **open bottom in all three controls** and rejects
those closed-bottom caches as mismatched inputs. Fresh native CI must
establish final acceptance; neither historical report is a pass for the
revised experiment. All original failed and preliminary results are retained.

Mass conservation, production liquid appearance, robust splashes, secondary
particles, two-way coupling, arbitrary complex moving obstacles and the full
Physics Laboratory remain unverified or unsupported. Signed surface volume is
a diagnostic and is not a certified mass-conservation measurement. No parent
Physics issue is closed by this profile.

The native control gate also requests `GEOMETRY` flow explicitly and checks
its retained setting, evolving nontrivial native mesh and fresh-process
reopen. Until that current-head gate executes, initial-volume mapping is
implemented with native execution still unverified; historical `INFLOW`
fixtures do not establish it.
