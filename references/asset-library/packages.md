# Exact asset packages

`scripts/asset_library_packages.py` packages verified, explicit library assets without changing their identities, versions, manifests, original bytes, evidence, or approval status. The dependency graph owner resolves each closure; the canonical library owner verifies and restores each version. Source-part transport and the portable archive guard remain the shared transport authorities. No second registry or extractor trust policy is introduced.

`create_package(graph, roots, destination, package_id=..., package_type=..., policy=..., context_files=...)` creates a new directory. Supported envelope types are individual asset, collection, prefab, scene, project and library. Scene/project envelopes require explicit context documents. Those documents retain their existing consumer validators: an envelope certifies the selected asset closure and exact documents, and does not infer arbitrary external references from unknown scene formats. Call a consumer's validated project adapter to select a complete project closure. The existing production project archive remains the authority for complete legacy production projects.

For independent scene instances that intentionally pin different versions of the same ID, use `scopes={'scene-a': [locator_a], 'scene-b': [locator_b]}` and an empty `roots` list. Each scope is validated independently by `DependencyGraph.lock`; global runtime version conflicts remain errors within each scope. Their union restores to one canonical library containing every exact version. Do not split a single runtime into separate scopes to conceal a real version conflict.

The versioned `asset-package.json` index binds its package identity, fixture label, policy, asset locations, canonical manifest paths, scoped lock paths, context files and the complete SHA-256/byte inventory. Blobs are deduplicated by hash. All inventoried own files, sources, license evidence and declared transitive asset links are included. Optional asset links are included too because current canonical registration requires those references to exist. An unavailable optional link therefore blocks package creation explicitly. There is no ambiguous latest-version substitution.

`verify_package(root)` checks the exact directory inventory, no-follow file reads, portable names, no links/special files or unlisted empty directories, bounded content, manifest hashes, evidence references and independently regenerated dependency locks. `inspect_package(root)` returns an `incomplete` diagnostic on failure without modifying the package. Manifest-only, missing-resource, modified-version, wrong-byte, extra-member or unreferenced-member packages never pass the completeness gate. Replacing missing content with different content does not repair the hash; restore the exact expected bytes.

`restore_package(root, new_destination)` verifies before publishing and stages a new isolated canonical library at `new_destination/library`. Original scoped lockfiles, the package index and explicit consumer documents are retained beside it. The source package remains unchanged, and an existing destination is never overwritten. Every restored immutable manifest is compared against its original. Original library alias resolution remains in the retained locks; consumers may resolve all restored exact references through the one restored library. Mutable annotations, collections, promotion events and host-local paths are not reclassified as immutable asset content or silently restored.

`create_archive`, `verify_package_archive` and `restore_package_archive` wrap the shared `portable_runs.verify_archive` strict ZIP guard. `create_transport`, `verify_transport` and `restore_transport` wrap existing `production_sources` ordered content-addressed parts, including each reconstructed file's hash. Missing/corrupt/reordered parts, false assembled hashes and extra transport members fail before library publication. No new ZIP reader bypasses the shared path, duplicate-member, symlink and inventory checks.

Limits are explicit and preserve the existing source-transport contract: at most 4095 inventoried package members plus the index, 4096 assets, 256 independent scopes, 256 context documents, 16384 inventoried parent directories, 64 MiB per file, 256 MiB expanded data and a 4 MiB index. ZIP input is additionally capped at 64 MiB; use multipart source transport for larger packages. Source transport retains its own stricter part-count/reference bounds. Operations are offline and explicit; destinations must be new. The caller owns private package roots while a call runs. Files are re-read and hashes rechecked at restoration/publication boundaries; this is not a sandbox against malicious concurrent writers of an owned root.

Completeness, licensing, technical readiness and review remain separate. Policy requires retained sources and license evidence by default. `gates` reports whether the requested use appears in the retained `allowed_uses` declaration, the original license/evidence, review status and distribution status. This is a declaration check, not a legal determination. Successful verification means complete exact bytes. It never supplies visual review, renderer execution, production readiness or public-distribution authorization.

Run the retained engineering demonstration with:

```bash
python scripts/demonstrate_asset_packages.py --destination NEW_DIRECTORY
```

It preserves real OBJ/license bytes through directory, ZIP and multipart restores; retains two immutable scoped versions; and proves missing/unrelated replacements fail until the exact payload returns. `tests/test_asset_library_packages.py` covers contracts and failure controls. `tests/test_rig_asset_packages.py` additionally exports real textured, skinned, morphed, animated GLB/glTF; packages and restores every dependency; independently reimports the relocated files and compares their evaluated data using the rig owner. These are engineering fixtures, not artistic approval or the complete two-scene rendered parent acceptance demonstration.
